Using sample data.

1. Numbers

Each number looks at one user's records in the current year. A count shows the total. A percentage shows how many of those records also meet an extra condition, such as tasks completed. A sum adds up a number or currency field, such as Amount.

2. Busiest month

Counts records per month and shows the peak. Example: object Opportunity, date Close Date, filter Stage = Closed Won.

3. Fun highlight

Finds the customer or contact each person interacted with most this year. Choose which records to count. Records created this year are counted.

4. Your year in one word

Rules are checked from the top. The first one that matches picks the word. If none match, the fallback is used.

5. Email message

Add your own words to the email. The first message sits under the greeting and the second at the bottom. Use {first} for the first name, {year} for the year and {word} for the person's one-word result. Line breaks are kept. Leave a box empty to skip it.

Connection help: how to connect an org

New to MCP?

MCP is a standard way to let Claude read from other apps. Each link to an app is called a connector. This page uses two: Salesforce, to read records, and Gmail, to send the emails. You add each one once to your claude.ai account, and this page then uses it.

Before you start

  • A claude.ai account that you are signed in to. On Team or Enterprise plans an owner may need to allow custom connectors.
  • A Salesforce login that can open Setup, usually a System Administrator.
  • About 10 minutes for the first org. After that it is quicker.

Part 1. Prepare Salesforce (once per org)

  1. In Salesforce, click the gear icon, then Setup. In Quick Find type MCP Servers and open it.
  2. Open the server you want to connect and click Activate. Check its status says Active. Server names change between releases, so choose the one that reads records (SObject All if it is listed).
  3. In Quick Find open External Client App Manager, then New External Client App.
  4. Name it Claude Salesforce MCP and enter your email as the contact.
  5. Under API (Enable OAuth Settings): tick Enable OAuth. Callback URL: https://claude.ai/api/mcp/auth_callback. Move the scopes mcp_api and refresh_token to Selected OAuth Scopes.
  6. Under Security, tick: Require secret for Web Server Flow, Require secret for Refresh Token Flow, Require Proof Key for Code Exchange (PKCE), Enable Refresh Token Rotation, and Issue JSON Web Token (JWT)-based access tokens for named users. Leave the rest, then click Create.
  7. On the app's Settings tab open OAuth Settings, then Consumer Key and Secret. Salesforce may email you a verification code. Copy the key and the secret and keep the secret in a password manager. Never paste the secret into this page or into a chat.

Part 2. Add the Salesforce connector to Claude

  1. In claude.ai or the Claude desktop app open Customize (some versions say Settings), then Connectors. Click + or Add, then Add custom connector.
  2. Name: type exactly Salesforce SObject All. This page looks for that name.
  3. Server URL for a production org: https://api.salesforce.com/platform/mcp/v1/platform/sobject-all
    For a sandbox or scratch org: https://api.salesforce.com/platform/mcp/v1/sandbox/platform/sobject-all
  4. Click Continue. Choose Use your own OAuth client (it can sit under Advanced settings). Paste the Consumer Key into OAuth Client ID and the secret into the secret box if it asks, then click Add.
  5. Click Connect. Salesforce opens. Sign in, and click Allow if asked.
  6. Optional: click Configure to see which tools are on. This page only needs the read tools: getUserInfo, getObjectSchema and soqlQuery.

Part 3. Add the Gmail connector

  1. In Customize, Connectors, open the directory, find Gmail and click Connect.
  2. Sign in with the Google account the recaps should come from. Every email is sent from that address.

Part 4. Use it here

  1. Reload this page and press Connect my Salesforce org. The first time, Claude asks whether this page may use your connector. Choose Allow.
  2. Check the green box. It must name the org you meant, and say Production or Sandbox. If not, see "Several orgs" below.
  3. When you send, Claude asks once more for Gmail. The test email shows you which inbox is connected.

Several orgs

  • Repeat Parts 1 and 2 for each org, using that org's own consumer key and URL.
  • Give every org's connector the same name, Salesforce SObject All. When more than one has that name, claude.ai asks you to pick one the first time this page reads Salesforce.
  • To switch orgs, turn off or disconnect the other connector in Customize, Connectors, reload this page, then press Connect again. The green box confirms which org you got.
  • When you sign in, use a private window or log out of Salesforce first. Your browser may reuse the last org you used.

Something went wrong?

  • "Connectors are not available in this view": open the page on claude.ai while signed in, as someone in the same organisation as the page's owner.
  • "No Salesforce connector found": the connector name does not match. Rename it to exactly Salesforce SObject All.
  • "Connection expired": reconnect it in Customize, Connectors.
  • Salesforce login is blocked: if your org does not allow login.salesforce.com, use your My Domain address in the server URL instead. Salesforce's guide, linked below, shows the format.
  • Object not found: custom objects such as Program__c only exist in orgs where they are deployed. Check the org in the green box.

The page only reads Salesforce. Nothing in your org is changed.

Read me

What this builds. A year-in-review for each person in your org, as a swipeable story and as an email. Each person sees only their own records.

What each person gets:

  1. Intro with their name and the year.
  2. Numbers: counts, percentages and totals of a field (such as revenue) from the objects you pick.
  3. Busiest month as a bar chart.
  4. Fun highlight, such as the contact they worked with most.
  5. Year in one word with an emoji and a sentence, chosen by your rules.

The email has the same five blocks, plus your own messages and a "Based on data as of" date. You can also attach each person's story as a file that opens in their browser.

How to use it.

  1. On the Connection tab, connect your org, or stay on sample data.
  2. On the Setup tab, fill in the numbers, busiest month, highlight, one-word rules and email message.
  3. On the Theme and Preview tab, pick a theme and check anyone's story and email side by side.
  4. On Send, email yourself a test, then send to the list.

How people receive it. Recaps are delivered by email, from the Send tab. Tick "Attach the interactive story" and each person also gets their own story file, which opens in their browser without signing in.

Sample preview

Sample only. It shows a made-up person, Priya Nair, with your current setup and theme. The numbers are invented and change as you edit.

Theme

Sets the colours, heading font, background pattern and a few headings for the story and the email. Changes show right away below. The presets use original styling only, with no logos or characters.

Story

How people view the story. The story goes out as an HTML file attached to the email. The person must download the attachment and open it in a web browser to view it. It does not play inside the email itself.

Email

Show the HTML to copy by hand

Email apps ignore scripts, so the email is a static version of the same story with the same numbers. Paste the HTML into an email template, or send it with Salesforce Flow or your email tool.

Test email

Emails go out from your own Gmail account, one at a time, to each person's email address in Salesforce. Send a test to yourself first. The Send button stays off until a test has gone out.

Every email has the subject "{first}, your Salesforce {year} in review", filled in for each person.

Each person gets their own file with only their numbers inside. The person must download the attachment and open it in a browser to view it. Some mail systems warn about or block attached web pages, so send yourself a test and open it from your inbox first.

The test uses the person chosen in "Preview for", with [TEST] added to the subject.
